# ADR-001 — pgx over database/sql (refined)

## Context

The project needs a PostgreSQL driver for marketplace-go. Go offers two main options: the standard database/sql interface with a driver underneath, or pgx, a PostgreSQL-specific driver and toolkit.

## Decision

Use pgx directly, not through database/sql.

## Alternatives considered

database/sql with a PostgreSQL driver underneath. Rejected because it abstracts away PostgreSQL-specific features and adds an unnecessary translation layer for a project that has no plan to support another database.

## Consequences

### Gained now:

Full support for PostgreSQL-specific types (JSONB, arrays, UUID) without manual conversion
Better connection pool control through pgxpool (MaxConns, MinConns)

### Gained for future use:

COPY protocol available for bulk product creation if the marketplace needs batch imports later (e.g. bulk-uploading a product catalog)
LISTEN/NOTIFY available if a future feature needs lightweight real-time updates without adding a message broker

### Given up:

Database portability — migrating away from PostgreSQL later would require rewriting the entire data access layer
Less familiarity for developers coming from the generic database/sql interface

Status: Accepted
